## 1. 注入内容：4 个键、6 个值

CLSID 固定：`{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}`

### 1.1 HKLM（Explorer 真正使用的一份）

| 键 | 值名 | 类型 | 内容 |
|---|---|---|---|
| `HKLM\SOFTWARE\Classes\CLSID\{CLSID}` | `(默认)` | REG_SZ | 空字符串 |
| `HKLM\SOFTWARE\Classes\CLSID\{CLSID}\InprocServer32` | `(默认)` | REG_SZ | **`<revolc_bho.dll 绝对路径>`** |
| `HKLM\SOFTWARE\Classes\CLSID\{CLSID}\InprocServer32` | `ThreadingModel` | REG_SZ | `Apartment` |
| `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Browser Helper Objects\{CLSID}` | `(默认)` | REG_SZ | `Revolc Tab Explorer Helper`（仅显示用） |

### 1.2 HKCU（同一套内容的兜底副本）

结构与 1.1 完全一致，只是根换成 `HKCU\Software\...`。

**结论：HKCU 对文件夹窗口无效**（Explorer 只读机器级 BHO 名单），它只在 IE 场景或早期测试时有点用。留着会让"看着注册了、其实没生效"的误判发生，所以卸载时必须一起清。

### 1.3 没有写的东西

Run 启动项 / 服务 / ContextMenuHandlers / ShellIconOverlay / 文件关联 / 环境变量 —— 一个都没有。`HKCR` 也没写（它是 `HKLM\Software\Classes` + `HKCU\Software\Classes` 的合成视图，不需要单独写）。

---

## 2. 为什么必须这两处

- **CLSID\InprocServer32**：COM 靠它把 CLSID 解析成 DLL 路径 + 线程模型。缺它 → Explorer 拿到 BHO 名单也找不到 DLL。
- **Browser Helper Objects\{CLSID}**：把一个 CLSID 登记进 Explorer 的 BHO 列表。**在列表里 = 每创建一个文件夹窗口就 LoadLibrary 一次并调 `SetSite`**，这就是接管机制本身。
- 两处**都在 HKLM** 才生效；只有 HKCU 的 CLSID 会被 Explorer 忽略（实测过，见 `Revolc_接管事故备忘.md`）。

## 3. 注入（安装）

管理员权限。**别用 `regsvr32`**（静默吞错），用 `reg.exe` 并显式验证。

```bat
:: 1) 清掉可能存在的旧值，避免路径残留
reg delete "HKLM\SOFTWARE\Classes\CLSID\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}" /f >nul 2>&1
reg delete "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Browser Helper Objects\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}" /f >nul 2>&1

:: 2) CLSID + InprocServer32
reg add "HKLM\SOFTWARE\Classes\CLSID\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}\InprocServer32" /ve /t REG_SZ /d "%DLL%" /f
reg add "HKLM\SOFTWARE\Classes\CLSID\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}\InprocServer32" /v ThreadingModel /t REG_SZ /d "Apartment" /f

:: 3) BHO 名单
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Browser Helper Objects\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}" /ve /t REG_SZ /d "Revolc Tab Explorer Helper" /f
```

### 位数视图陷阱

`reg.exe` 的行为取决于**调用它的进程位数**：

| 调用者 | 默认写入位置 |
|---|---|
| 64 位 cmd / 64 位进程 | `HKLM\SOFTWARE\...`（正确） |
| 32 位进程（含 32 位安装器） | `HKLM\SOFTWARE\WOW6432Node\...`（**错**） |

应对：显式加 `/reg:64`，或确认安装器本身是 64 位。PowerShell 同理，`HKLM:\SOFTWARE` 在 32 位宿主里会被重定向，需要 `-PSProvider Registry` 配合 `[Microsoft.Win32.Registry]::LocalMachine` + `RegistryView::Registry64`，最简单还是调 `reg.exe /reg:64`。

### 先决条件检查

1. `revolc_bho.dll` 存在且是 **release 构建**（debug 版进 Explorer 会出问题）。
2. 路径**固定**（安装目录）。当前调试版指向 `D:\Projects\file-explorer\Revolc\target\release\revolc_bho.dll`，`cargo clean` 就会变成悬空注册。
3. DLL 位数 = 系统位数（当前是 x64）。

## 4. 验证

```bat
reg query "HKLM\SOFTWARE\Classes\CLSID\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}\InprocServer32" /reg:64
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Browser Helper Objects\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}" /reg:64
```

PowerShell 版（读当前真实状态）：

```powershell
$c='{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}'
foreach($p in @(
  "HKLM:\SOFTWARE\Classes\CLSID\$c\InprocServer32",
  "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Browser Helper Objects\$c")){
  if(Test-Path $p){ "$p => " + (Get-Item $p).GetValue('') } else { "$p => MISSING" }
}
```

**通过判据（三条全中）**：
1. 两个 HKLM 键都存在；
2. `InprocServer32` 的默认值 == 当前部署的 DLL 绝对路径；
3. 该路径下文件存在。

只有 `SetSite` 真的被调用才算端到端通（见 §7 的运行时验证）。

## 5. 取消注入

```bat
reg delete "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Browser Helper Objects\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}" /f
reg delete "HKLM\SOFTWARE\Classes\CLSID\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}" /f
reg delete "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Browser Helper Objects\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}" /f
reg delete "HKCU\SOFTWARE\Classes\CLSID\{9F1C4E8B-6A2D-4E7B-8C13-5D04F7A2B916}" /f
```

顺序要求：

1. **先让 Revolc 退出**（托盘「退出」或 `revolc.exe --shutdown`），让 `release_all` 把吸收的窗口还回桌面；
2. 再删键；
3. 最后重启 Explorer（`taskkill /f /im explorer.exe & start explorer`）—— 不重启的话，**已打开的窗口仍持有已加载的 DLL**，只是新窗口不再接管。

程序内也有这条路径：`revolc.toml` 改 `[takeover] mode` 为非 `redirect`，启动时 `takeover::ensure_bho_registered` 会自动清 HKLM+HKCU 两处（HKLM 份需要 UAC）。

## 6. 设置页「注入 / 取消注入」开关设计

### 6.1 状态机（UI 四态）

| 状态 | 判定 | UI |
|---|---|---|
| 未注入 | HKLM 两键任一缺失 | 开关=关，可点"启用接管" |
| 已注入（当前版本） | 两键在 且 路径 == 当前 DLL 路径 且 文件存在 | 开关=开，显示路径 |
| 已注入（路径过期） | 两键在 但路径 != 当前 DLL 或文件不存在 | 开关=开 + 黄色警告「注入指向 %path%，需修复」 |
| 无权限 / 被拦截 | 写 HKLM 返回 access denied，或安全软件拦截 | 提示"需要管理员权限"或"被安全软件拦截" |

### 6.2 动作

- **启用**：`ShellExecuteEx(runas)` 跑一个 helper（`reg import 临时.reg`，或 `revolc.exe --register` 自带提权分支）。UAC 被拒 → 回到原状态并提示，**不要**乐观地把开关拨到"开"。
- **禁用**：同样提权删除 + 清 HKCU 兜底键。
- **重启 Explorer 按钮**：所有 BHO 变更都要它才彻底生效。点之前明确警告「会关闭所有资源管理器窗口」，并先把 Revolc 的吸收窗口 release 掉。

### 6.3 必须写进代码的坑（都是踩过的）

1. 提权必须走 `runas`，`asInvoker` 下写 HKLM 一定失败。
2. 32/64 位视图：统一 `/reg:64`。
3. **不要**用 `regsvr32 /s` 判成功（它会静默失败）。
4. 注入成功后要**回读验证**，不能只看返回码。
5. 路径变更（升级/移动安装目录）必须重写 InprocServer32，否则 Explorer 加载旧 DLL 或加载失败。
6. 取消注入前先退出 Revolc，否则吸收中的窗口随进程一起销毁。
7. HKCU 兜底键一起清，别留下"半注册"状态。
8. 安全软件可能拦 BHO：失败要给出可读原因，而不是"操作失败"。

### 6.4 绿色版的现实边界

**做不到"零注入"**：Explorer 只认 HKLM 的 BHO 名单，HKCU 无效。所以绿色版只能是：

- 免安装（不写 Program Files、不建服务、不写 Run）；
- 注入/取消注入仍需管理员 + 写 HKLM（`reg.exe` 调用即可，不必装任何东西）；
- "绿色卸载" = 删这两个键 + 删 `%APPDATA%\revolc`，系统零残留。

如果将来要做真正的"零注册表"接管，方向就换成：改文件夹打开方式（`Folder\shell\open\command`）或常驻钩子 —— 那是另一套架构，不在当前 BHO 方案内。

## 7. 运行时验证（端到端）

1. 建一个探针文件：`%APPDATA%\revolc\bho.debug`（内容随意）。
2. 开一个文件夹窗口。
3. 看 `%APPDATA%\revolc\bho.log` 是否出现 `SetSite (notify only)`：
   - 有 → BHO 已被加载并回调；
   - 无 → 键在但 DLL 没加载（路径错 / 位数错 / 被安全软件拦）。
4. 看 `%APPDATA%\revolc\logs\revolc.log.*` 是否出现 `absorb notify received` / `explorer window absorbed`。

### 10.3 记录里原先缺的三件事（已补）

1. **这不是"一次性注入"，是反复写删过很多次。**
   从 `%APPDATA%\revolc\bho.log` 与 `logs\revolc.log.*` 统计：

   | 事件 | 次数 |
   |---|---|
   | `CLSID written to HKLM` / `BHO key written to HKLM` | 13 / 16 |
   | `CLSID HKLM denied` / `HKLM denied`（降级写 HKCU） | 9 / 12 |
   | `elevated regsvr32 launched` | 9 |
   | `HKLM BHO key present, requesting elevation for unregister` | 4 |

   含义：**注册表的当前状态只是"最后一次写入"的结果**，之前的路径/存在性都不可追溯。想留痕就得靠这份备忘 + `.reg` 备份，而不是指望注册表。

2. **HKCU 的键可能是程序自己写的，不是用户手动注入的。**
   以非管理员身份启动 `revolc.exe` 时，`DllRegisterServer` 会走 HKCU 兜底分支（日志 `HKLM denied`）。所以：
   - 「是否已注入」**必须只看 HKLM**；
   - 设置页里 HKCU 那两份应当视为"垃圾/待清理"，而不是状态来源。

3. **运行时痕迹不在注册表里**，卸载时要一并考虑：

   | 位置 | 内容 |
   |---|---|
   | `%APPDATA%\revolc\revolc.toml` | 配置 |
   | `%APPDATA%\revolc\bho.log` | BHO 日志（仅 `bho.debug` 存在时写） |
   | `%APPDATA%\revolc\logs\revolc.log.*` | 主程序日志 |
   | `%APPDATA%\revolc\crash\` | 崩溃转储（`crash.rs` 的 handler 生成） |
   | 已加载 `revolc_bho.dll` 的 explorer.exe 进程 | 重启 Explorer 即清除 |

### 10.4 已知的"看着像问题、其实不是"

- `crash\crash-*.txt` 里如果出现 `revolc::crash::selftest (crash.rs:265)`，那是崩溃处理器自测**主动**触发的空指针，不代表程序崩溃。
- 2026-11-18 那份 346MB 的日志是**旧构建**留下的：单条 `tabbar NCHITTEST ...` 被记了 352 万次（鼠标每移动一次写一行）。当前源码里已无该语句。旧日志可直接删除。

## 11. 完整备份与「清理→重注入」实验

### 11.1 先纠正一个直觉

**`.reg` 的导入是合并（merge），不是覆盖（restore）。**

| 手段 | 能否删除"备份之后新增的键" | 适用 |
|---|---|---|
| `reg export/import` 单个/多个键 | ❌ 不能 | 精确备份恢复 Revolc 这几项（够用） |
| `reg export/import` 整个 hive（HKLM/HKCU/…） | ❌ 不能 | 只适合"把值写回去"，不是回滚 |
| 系统还原点 / VSS 快照 | ✅ 能 | **实验前的真正安全网** |
| WinPE 离线还原 hive 文件 | ✅ 能（最彻底） | 系统盘起不来时 |

所以本实验的安全网用**还原点**，`.reg` 只用来精确搬运 Revolc 的那 4 个键。

### 11.2 四层备份，按需要选

| 层级 | 命令 | 体积/耗时 | 作用 |
|---|---|---|---|
| L1 精确 4 键 | `reg export` 4 次 | KB / 1 秒 | 恢复/比对 Revolc 注入状态 |
| L2 全 hive 文本 | `reg export HKLM/HKCU/HKCR/HKU/HKCC` | 数百 MB / 数分钟 | 全机注册表快照，**只可合并回写** |
| L3 还原点 | `Checkpoint-Computer` | 分钟级 | 真回滚（推荐做） |
| L4 离线 hive | WinPE + 覆盖 `SYSTEM/SOFTWARE/SAM/SECURITY/DEFAULT/NTUSER.DAT` | 重启进 PE | 最彻底，风险最高 |

L2 实操注意：
- `HKCR` 是 `HKLM\Software\Classes` + `HKCU\Software\Classes` 的合成视图，导出无妨但不必单独用它还原；
- `HKCU` 导出时若有个别键被占用会报"拒绝访问"，属正常；
- 导入 L2 时要管理员，且**不要**指望它删掉后加的东西。

### 11.3 实验协议（脚本：`tools/registry-experiment.ps1`）

前置：管理员 PowerShell；Revolc 先退出（脚本 `clean` 会自动 `--shutdown`）。

| 步 | 动作 | 期望观测 | 判据 |
|---|---|---|---|
| 0 | `-Action backup` | 目录里出现 5 个 hive 备份 + 4 个 revole 键备份 | 文件存在且非 0 字节 |
| 0b | `-Action restore-point` | 还原点创建成功 | 失败先启用系统保护 |
| 1 | 基线：开 2 个文件夹 | 都进 tab | `revolc.log` 有 `absorbed into tab` |
| 2 | `-Action clean`，然后**重启 Explorer** | 开文件夹 → 系统原生 FE，不进 tab | `bho.log` 无新增 `SetSite`；`revolc.log` 无 `absorb notify received` |
| 3 | `-Action inject`，然后**重启 Explorer** | 开文件夹 → 又进 tab | 同 1 的判据 |
| 4a | 若 3 失败：`-Action restore`（合并式回写） | 恢复注入 | `-Action verify` 显示「已注入（可用）」 |
| 4b | 若仍失败：还原点回滚 | 回到实验前状态 | 系统正常，再 `-Action verify` |

**第 2 步必须重启 Explorer**：注册表删了但已加载 DLL 的 explorer 进程不会卸载，不重启会误判成"清理无效"。

### 11.4 清理后"应该不好用"的精确含义

| 现象 | 说明 |
|---|---|
| 双击文件夹 → 系统 FE 窗口，不进 tab | 正常（这是预期的"失效"） |
| Revolc 主窗口还在、托盘还在 | 正常，它只是收不到通知了 |
| `bho.log` 停止增长 | 正常（前提：`bho.debug` 探针存在） |
| 已打开的旧 tab 内容还在 | 正常，那是之前吸收的窗口 |

### 11.5 失败时的最小恢复顺序

1. `-Action inject`（最轻，通常就够）
2. `-Action restore`（用 4 键备份合并回写）
3. 还原点回滚（系统级）
4. WinPE 离线 hive（最后的选项）
