# 双进程架构设计（浏览器模型）

> 状态：Phase 2 已实施（分支 `redesign/tray-exe-phase2`）。目标形态、迁移路线与验收标准。
> 背景讨论：2026-11-20，源头是多窗口下首窗关不掉、FE 被吸走、托盘「打开 Revolc」语义歧义。

## 1. 问题：旧架构把"常驻"绑在第一个窗口上

- 第一个窗口 `owns_tray`，redirect 模式下 X = 隐藏到托盘，关不掉；
- 托盘「打开 Revolc」要回答"把谁放前台"——多窗口下无解（最后激活只是勉强说得过去）；
- extra 窗口关闭时 `release_all` 把 FE 放回桌面，但不写排除表，首窗 sweep 把它当 stray
  收成新 tab（"被吸走"）；
- BHO 的 `FindWindowW("RevolcMain")` 只命中"某一个"窗口（M3.2b 遗留）。

根因：**"进程常驻"这个需求被实现成了"第一个窗口不许关"**。窗口语义和进程生命周期被焊死在一起。

## 2. 参照系：浏览器怎么做

调研结论（2026-11-20）：

- 浏览器**不是**"双击 exe 开新进程"。Chrome/Edge/Firefox 每 profile 单实例（Chromium
  `ProcessSingleton` 锁 + IPC 转发）：二次启动把参数转发给老进程后退出，由老进程开新窗口。
  多进程的是 renderer/GPU/utility（渲染隔离），窗口全在唯一 browser process。
- 多窗口之间**没有协商**：进程内有唯一记账者（`BrowserList`，按最近激活排序），
  窗口激活时上报，打开的东西去哪个窗口由记账者拍板。
- 浏览器**没有托盘图标**——任务栏就是窗口列表；全关即退出，没有"常驻"需求。
- Clover 取证（`docs/交接文档.md` §二阶段参照系）：Clover 的多窗口/单实例/转发全是
  Chromium 原生；托盘不是 Clover 的（解包零 `Shell_NotifyIcon`），是 Revolc 为 redirect 自己发明的。

## 3. 目标形态（两个 exe）

```
tray.exe（可选常驻）                 revolc.exe ×N（每窗口一进程）
├─ BHO 通知兜底目标                  ├─ 每个窗口都是普通窗口
├─ 新建窗口 = 启动器                 ├─ X = 真关
├─ 窗口列表 = EnumWindows+实时标题    ├─ sweep 只管自己的死 view 清理
├─ 全部关闭 / 退出接管               └─ 0 窗口存活时进程退出
└─ 崩溃/未启动不影响任何窗口
```

核心原则：

1. **窗口进程自洽**：不启动托盘时一切功能正常；全关 = 接管停止（浏览器语义）。
2. **托盘可有可无**：只是"新建窗口 / 窗口列表 / 全部关闭 / 退出接管"的快捷通道。
   托盘在跑且检测到 0 窗口时，兜底接 BHO 通知、拉起新窗口接管。
3. **记账者唯一**：谁是"最后激活窗口"由账本决定，窗口之间无协商。
   终态（Phase 2+）：账本放 tray，用 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 被动记账，
   窗口进程零改动零协议。Phase 1（单进程）账本仍是进程内的 `LAST_ACTIVE`。
4. **认领唯一**：任一时刻只有一个进程/窗口收下 BHO 通知，杜绝双吸收竞态
   （2026-11-17 同 HWND 双吸收僵尸事故）。

## 4. Phase 1（单进程内解绑，本分支）

不改进程模型，先把语义纠正过来。验收全部通过后才进 Phase 2。

| # | 改动 | 内容 |
|---|------|------|
| 1 | 配置项 | 新增 `[tray] enabled`（默认 `true`）。启动时读取；热更暂不生效（需重启，Phase 1 接受） |
| 2 | X 真关 | 删除 `WM_CLOSE` / `close_tab` / `drop_dead_views` 的"隐藏到托盘"分支。所有窗口 X = `DestroyWindow` |
| 3 | 常驻窗口 | redirect 且 tray.enabled 时，启动即创建隐藏顶层窗口 `RevolcResident`：持有托盘图标、UIPI 放行 BHO 通知、处理托盘菜单；最后一个主窗口关闭后进程靠它存活 |
| 4 | 托盘迁移 | 图标从首个主窗口移到 resident。菜单：新建窗口 / 退出。左键 = 新建窗口（窗口列表 Phase 2 再做） |
| 5 | BHO 回退 | `notify_revolc` 先找 `RevolcMain`，找不到再找 `RevolcResident`（0 窗口兜底） |
| 6 | `--shutdown` | 同样先找主窗口、找不到找 resident |
| 7 | FE 吸附修复 | `release_all` 把释放的 HWND 写入**进程级排除表**（TTL 同 `EXCLUDE_TTL`），所有窗口的 sweep 合并该表 → extra 窗关闭后 FE 留在桌面，不被别的窗口吸走 |

Phase 1 之后的行为表：

| 场景 | tray.enabled = true | tray.enabled = false |
|---|---|---|
| 双击文件夹（有窗口） | 吸进最后激活窗口 | 同左 |
| X 关任意窗口 | 真关，FE 留在桌面 | 同左 |
| 关最后一个窗口 | 进程缩到 resident，托盘还在 | 进程退出，接管停止 |
| 0 窗口时双击文件夹 | resident 拉起新窗口吸收 | 不接管（普通 Explorer） |
| 托盘「退出」 | 恢复所有 FE + 退出 | （无托盘） |

## 5. Phase 2（拆 tray.exe）—— 已实施

产物：`revolc-tray.exe`（可选常驻）+ `revolc.exe` ×N（每窗口一进程）。

- **共享层 `common/`**：`config` / `logging` / `crash` / `icon` / `takeover` / `messages`
  + 新 `ledger`。原 root 模块改为 re-export，路径不变。
- **账本 `Local\RevolcWindowLedger`**：固定 32 字节文件映射，`generation` 奇偶
  seqlock 保护 `last_active` HWND + tray PID。tray 的
  `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 是主写者；每个窗口在 WM_ACTIVATE
  时回写同一值（`note_active`，不覆盖 tray PID），所以**不装 tray 也能用**。
  账本无有效值时按"最小可见 RevolcMain HWND"确定性认领，杜绝 timer 抢单。
- **`revolc-tray.exe`**：单实例锁 `Local\RevolcTraySingleInstance`；托盘菜单
  = 新建窗口 / 窗口列表（EnumWindows + GetWindowText 实时）/ 全部关闭 /
  退出接管；BHO 注册与注销只由它做；0 窗口时收到 BHO 通知则 spawn `revolc.exe`；
  独立日志 `revolc-tray.log`；config watcher 只 watch `revolc.toml` + 500ms 防抖。
- **BHO**：`notify_revolc` 由 `FindWindowW` 单点改为 `EnumWindows` 广播给所有
  `RevolcMain`，并额外通知 tray 窗口作 0 窗口兜底；窗口侧收到通知后先问
  `may_adopt()`，非账本得主不进 burst。
- **`revolc.exe`**：删除 `resident` / `ui/tray` / `ensure_single_instance` /
  BHO 注册；WM_DESTROY 即退出；`--shutdown` 广播所有窗口 + tray；
  config watcher 同样收敛为单文件 + 防抖。
- **未做**：注册表 Run 自启动（留给用户自行设置）；M3.3 跨进程拖 tab 的
  完整改造（吸收链路已证明跨进程 `SetParent` 可行，但拖动交互尚未迁移）。

## 6. 已知取舍

- `tray.enabled` 改动仍需重启 tray（tray 不热更自己的启用状态）。
- 不启动 tray 时 BHO 不再自动注册；若此前已注册，BHO 通知仍能广播到窗口进程，
  但"退出接管"的注销要由 tray 或 `revolc.exe --shutdown` 完成。
- 强杀窗口进程仍会留下被接管的 FE 窗口（固有风险，见 README）。
