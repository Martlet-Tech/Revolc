## 1. 项目是什么

Revolc = Clover（把系统资源管理器变成多标签的 shell 扩展）的 Rust 重制版。目标架构已验证可行：

- **接管机制**：Explorer BHO（COM DLL，`revolc_bho.dll`）注册进 `HKLM\...\Explorer\Browser Helper Objects`，Explorer 每开一个文件夹窗口就加载它并调 `SetSite`；BHO 只发一条注册窗口消息 `RevolcAbsorbExplorer` 给 Revolc 主窗口（**不碰 site 对象**），Revolc 用 `EnumWindows` 找到新开的 `CabinetWClass` 窗口，`SetParent` 搬进自己的 tab（tab 内容 = 真实 Explorer 窗口，ribbon 天然存在）。
- **取消接管** = 注销 BHO，系统 Explorer 100% 原样。
- 配置：`%APPDATA%\revolc\revolc.toml`，`[takeover] mode = "off" | "redirect"`，热重载。

## 2. 当前状态（本次交付）

- **redirect 接管链路全线工作**：双击文件夹 → FE 闪现 → ~0.2-0.4s 吸收进 tab；Ctrl+W 关 tab 恢复窗口；关闭后驻留托盘。
- **吸收改为「通知 + 自适应扫描」双通道**（2026-11-17 下午，commit `2f0321d` / `376d0a8`）：BHO 的 SetSite 只是提示（它在新窗口真正显示前就触发），主窗口用 `SetTimer` 扫桌面上的 `CabinetWClass`，凡是不属于 Revolc 的全部收编。**扫描速率是自适应的**：收到通知（或我们自己 spawn 了 Explorer）→ 15ms 快扫持续 1.5s；其余时间 200ms 一次保底（单次 EnumWindows 亚毫秒，CPU 占比远低于 1%）。旧实现只给通知路径 25×15ms=375ms 的窗口期，超时就 `WARN no new folder window found after notify`，窗口永久留在系统 FE —— 这就是「文件夹打开到了自带 FE」的根因。
  为什么不能纯事件驱动：通知会丢（BHO 未注册/窗口在注册前创建/Revolc 忙），丢一次就永久留在 FE，必须有个低频兜底。
- **客户区对齐 + 全量重绘（commit `25a5fbd`，架构要点）**：吸收窗口**不能**按窗口矩形摆，必须按**客户区**摆。`host::nc_metrics()` 实测 `GetWindowRect` 与 `GetClientRect` 之差（`MapWindowPoints` 到屏幕坐标），`Absorbed::place_client()` 把客户区左上角钉在 `(0, TABBAR_HEIGHT)`，非客户区被顶到我们客户区之外、由标签栏遮住。NC 高不是常数（剥掉 caption 时≈0，Explorer 重新套用样式时≈30，最大化/还原还会变），所以 `laid_out` 缓存 key 里带上 NC 值，NC 一变就重摆。**不要**把窗口挪到屏幕外、也不要用 0x0 尺寸：SetParent 之后它已经不可见，0x0 会触发 Explorer 重建浏览器布局。残影的治法是 `RedrawWindow(RDW_INVALIDATE|RDW_ERASE|RDW_ALLCHILDREN|RDW_UPDATENOW)` —— 我们开了 `WS_CLIPCHILDREN`，自己的 invalidate 碰不到子窗口让出的区域。
- **外来条带（commit `9fbddbf`）**：截图显示标签栏与 ribbon 之间有一条**不属于当前视图**的 Explorer 界面（某张图里是地址栏、另一张是列标题）。三条防线：①`Absorbed::ensure_stripped` 每次扫描复查窗口样式（Explorer 导航时会把 WS_CAPTION 加回来 → 标题栏条带重现）；②扫描时枚举主窗口的直接子窗口，凡不是标签栏、也不是已追踪视图的**全部隐藏**并 warn（带 class + rect）；③`WM_SIZE` 打 `layout` 证据日志：客户区、标签栏矩形、每个子窗口的 class/rect/visible/nc。下次再报此问题，直接看日志而不是截图。
- **缩放/重绘（commit `e77cf45`）**：最大化/还原后出现「两条标签栏 + 黑带」→ 主窗口没有背景刷，tab 区没盖住的像素保留上一帧；现在 `WM_ERASEBKGND` 用 tabbar 背景色填充、`WM_SIZE` 全量重绘、主窗口加 `WS_CLIPCHILDREN`（擦除不会盖到子窗口）。`Absorbed::resize` 改回**同步**（`SWP_ASYNCWINDOWPOS` 会让吸收窗口比宿主晚一帧，表现为标签栏下方 20px 黑缝 + 旧位置残影）；`layout()` 显式 `InvalidateRect(tabbar)`（`MoveWindow` 在尺寸没变时不重绘，正是最大化的情形）。
- **焦点与布局（commit `6366a82`）**：①地址栏能点不能打字 → 输入队列问题，`AttachThreadInput` 在「我们是活动窗口」期间挂住当前 tab 的 Explorer 线程，`WM_ACTIVATE(WA_INACTIVE)` 与切 tab 时卸载（合并队列也会合并卡死）；②两个 Explorer 界面叠着显示 → `absorb` 不再 `SWP_SHOWWINDOW`（原来会在 (0,0) 用桌面尺寸闪一下）、吸收后立即 resize、每次扫描用 `IsWindowVisible` 复核可见性并强制纠偏（Explorer 导航完会自己 ShowWindow）；③标签栏每次布局重新 `HWND_TOP` 抬到吸收窗口之上；④几何下发改给 `laid_out` 去重，避免 200ms 扫描反复跨进程 SetWindowPos。
- **其它稳定性改动**：`IShellWindows` 只在保留 tab 上调用（原先每次吸收都跨进程 COM，卡 UI 线程）；用户自己关掉的 Explorer 窗口对应的 tab 自动回收；跨进程 `SetWindowPos` 改 `SWP_ASYNCWINDOWPOS`（同步会阻塞在 Explorer 输入队列上，UI 线程跟着假死）；BHO 的 SetSite 先发通知、文件日志改为可选（`%APPDATA%\revolc\bho.debug` 存在才写）。
- **界面（commit `8d46b30`）**：标签文案改为跟 Explorer 窗口标题实时同步（`Tab::label` 与 `Tab::path` 分离，扫描时刷新）；`Ctrl+T`/`+` 用 `IShellWindows` 解析当前实际路径（不再用陈旧 path）；`tab_radius` 真正生效（`CreateRoundRectRgn`）；tab 宽自适应 90–190px 填满标签栏；长名省略号；`+` 有了自己的胶囊底。**`WM_CLOSE` 改为收托盘**（Clover 语义），真退出走托盘菜单或 `revolc.exe --shutdown`（内部是 `WM_APP_QUIT`）。
- **新增 `revolc.exe --shutdown`**：给运行中实例发 `WM_APP_QUIT`（不是 WM_CLOSE，后者现在只收托盘），优雅恢复窗口后退出。**不要用 taskkill**（子窗口随宿主销毁）。
- **图标（2026-11-18）**：`assets/icon.ico`（10 个尺寸 16–256，白底已抠成透明）是唯一图标源。`build.rs` 用 SDK 自带的 `rc.exe` 把 `1 ICON "icon.ico"` 编成 `.res` 后 `rustc-link-arg` 进 exe（不引入 build-dependency；找不到 rc.exe 只告警不失败）。运行时 `src/ui/icon.rs` 用 `LoadImageW(资源 id 1, SM_CXICON/SM_CXSMICON)` 取同一个资源，供 ①窗口类 hIcon/hIconSm ②WM_CREATE 里 `WM_SETICON`（任务栏按钮读的是窗口图标，不是类图标）③托盘（替代原先的 `IDI_APPLICATION`）。诊断：`cargo run --release --example icon_probe` 会打开 exe 验证 id 1 在两个 metric 下都可加载；改名/换图后重跑 `tools/make_icon.ps1` 即可（PowerShell + GDI+，无需 Pillow）。
- 构建：`cargo build --release`（主程序）+ `cargo build --release -p revolc-bho`（BHO DLL，**不会随默认构建**，注意 crate 名是连字符 `revolc-bho`）。
- 测试：`cargo test`（6/6 通过）。
- 注册（管理员，别用 regsvr32，静默吞错）：见 `docs/接管事故备忘.md` 中的 `reg.exe /reg:64` 三条命令；注销 = `reg delete` 同两处。**注入内容、验证判据、设置页开关设计、安装包片段全部整理在 `docs/注册表注入备忘.md`**，配套 `docs/registry/backup-20261118.reg` / `clear-20261118.reg`（UTF-16LE）与 `tools/registry-experiment.ps1`。
- 已知体验残留：开/关 tab 时 FE 有瞬间闪烁（re-parent 架构固有，Clover 原版同款）。

### M3 第一阶段（2026-11-18，分支 `m3-integrated-titlebar`，commit 39f0ded）

Chrome 式一体化标题栏：窗口无 `WS_CAPTION`，tab 条就是标题栏，右侧画 min/max/close。

- `WM_NCCALCSIZE` 返回 0（客户区 = 窗口矩形）；**最大化时必须内缩** `SM_CXSIZEFRAME + SM_CXPADDEDBORDER`，
  否则内容四边各被不可见边框切掉 ~7px。
- 命中全在主窗口：`HTCAPTION`（空白条带）+ 8 条缩放边框（最大化时不给边框码，否则屏幕边缘显示 resize 光标）。
  拖拽/双击最大化由 `DefWindowProc` 完成。**三个按钮不给 `HTMIN/MAX/CLOSE`**：无 NC 区的窗口上报非客户区按钮，
  系统给不出位置，按下后点击无效并在按钮上画一个白色方块（2026-11-18 实测，本机 Win10）。
  改成 `HTCLIENT` + `caption_action()` 自己执行（最小化 / 最大化还原 / `WM_CLOSE` 收托盘）。
- **别把标题栏做成子窗口**：子窗口的 `HTTRANSPARENT` 只向上转发**客户区**命中，user32 会回头狂问子窗口
  （实测 1.5ms 内 30 次），点击既不进父也不进子。这就是 tab 条从子窗口改成 `TabBar{paint,hit}` 的原因。
- 悬停状态在 `WM_NCHITTEST` 里顺手更新（每次鼠标移动必经），配 `TME_LEAVE|TME_NONCLIENT` 清；
  主题新增 `caption_hover` / `caption_close_hover`。
- **吸收窗口必须被裁掉顶部 overhang**（commit `1cd802b`）：`place_client` 为了让 ribbon 落在 y=34，
  把 Explorer 子窗口上移 `band`（实测 31px）、并加高等量，于是那 31px 悬在标题栏上。
  子窗口必然压过父窗口的绘制**和**命中——先表现为"标题栏是一条细黑线"，然后 tab/`+`/X/三按钮全失效。
  `band` 在吸收瞬间是 0、Explorer 套完自定义边框才变 31，所以表现为"有时好使"。
  治法是 `clip_above_content()`：`SetWindowRgn` 把内容区以上切掉（区域外不算这个窗口，绘制与命中都归还父窗口），
  每次摆位重算，`restore()` 清掉。

### 托盘左键（2026-11-18，commit `f164f8a`，已合并 master）

原先托盘只认 `WM_LBUTTONDBLCLK`，左键单击完全没反应。现在左键单击 = 到前台。

- **可见性与前台是两个维度，代码里也拆成两步**：`App::surface()`（未改）只管可见性，且只对「已最小化 / 已隐藏」的窗口动手，
  所以**最大化窗口不会被还原**；`host::activate()` 只管 z-order / 激活，**从不调用 SW_RESTORE**（SW_SHOWNORMAL/SW_RESTORE 会顺带干掉 maximize 状态）。
- `activate` 为什么必须 `AttachThreadInput`：点托盘时前台是任务栏（explorer.exe），后台进程直接 `SetForegroundWindow` 只会让任务栏按钮闪一下，
  前台锁会吞掉调用。临时挂到当前前台线程的输入队列上再调才生效。
- **别对这个 attach 做无脑 detach**：`AttachThreadInput` 不是引用计数，而 `sync_input_queue` 对活动 tab 的 Explorer 线程保持着**持久** attach。
  若前台线程恰好就是那个 tid，attach/detach 一过就把持久链拆了（症状：地址栏能点不能打字）。所以 `activate` 接收 `attached_tid` 并跳过这一对。
- `WM_LBUTTONUP` 与 `WM_LBUTTONDBLCLK` 都走同一条路：双击前的那个 UP 已经把活干完了，第二次调用是幂等的（不 toggle，不做「再点一次就最小化」）。
- 诊断：`cargo run --release --example tray_click` 发与 Shell 相同的消息，打印前后 `GetForegroundWindow`，用来区分「消息没到」和「激活被前台锁拒」。

### M3 前置步骤：标签拖拽重排（2026-11-18，commit `1aadf9e`）

在当前窗口的标题栏内拖 tab 换位，为二阶段「拖出去成新窗口」打地基。

- **判定位规则是中心线**（`tabbar::landing`，纯几何、可单测）：循环得到插入槽位 `0..=n`，再对「自己已占一格」做修正
  `insert > from ? insert - 1 : insert`。不修正的话拖动第一个像素就会报移位。等宽槽位下，被拖 tab 的中心越过邻居中心才换位
  ——这就是浏览器的感觉。
- **判定用未 clamp 的位置，绘制才 clamp**（commit `c3be110`）：早期版本先把左边缘钉在 `GUTTER` 再判定，于是被拖 tab 的中心
  永远越不过第 1 个 tab 的中心线，「2# 拖到 1#」静默失效（指针到哪儿都返回「不换」）。现在 `Drag` 存 `raw`，`landing` 吃 raw，
  `Drag::left()` 只负责画的时候把 tab 压在条带里。两端因此都可达，且左右判定保持严格对称（`center < mid` 才算没越过）。
- 槽位等宽，所以**重排不移动任何窗口**：`App::move_tab` 同步 `tabs` / `views`，并把 `laid_out` 的索引就地重定向，
  **不清缓存**（清了会让下一次 sweep 付一次跨进程 `SetWindowPos`）。
- 拖动阈值用 `SM_CXDRAG`（user32 自己那套）；`SetCapture` 保证移出窗口仍跟手；起拖前先 `activate` 被拖的 tab（浏览器语义）。
- **拖动期间整个窗口返回 `HTCLIENT`**：标签条上方是 `HTCAPTION`，拖到那里会变成 `WM_NCMOUSEMOVE`，tab 会僵在半空。
- 被拖 tab **最后绘制**（浮在所有槽位之上），它离开的槽位留空显示 band 底色，等价于别的 tab 让位；`hover` 在拖动期间冻结
  （`update_hover` 直接 return），否则经过每个槽位都会闪。
- 已知未做：拖出窗口分离（二阶段）；让位动画（等宽下视觉等价，暂不需要）。

### M3.2a 多窗口地基（2026-11-19）

单窗口不是“还没做多窗口”，而是**写死**在四个地方：类注册失败即返回 `Err`、`WM_DESTROY` 无条件 `PostQuitMessage`、
托盘绑窗口 hwnd、`TranslateAcceleratorW` 固定用第一个窗口。这一版把它们全部拆开，并接上托盘的「新建窗口」。

| 改动 | 原行为 | 现行为 |
|---|---|---|
| 类注册 | 第二次 `RegisterClassExW` 失败 → 建不出第二个窗口 | `ensure_class()` 吞掉 `ERROR_CLASS_ALREADY_EXISTS(1410)` |
| 退出 | 任一窗口 `WM_DESTROY` → `PostQuitMessage` | `LIVE_WINDOWS` 计数归零才退；`WM_APP_QUIT` 遍历销毁全部窗口 |
| 加速键 | 固定在首个窗口的 HWND 上 | 按消息的焦点控件找 `GA_ROOT` 所属窗口，用**那个窗口自己**的 HACCEL |
| 托盘 | 跟在窗口上，窗口没了图标就没了 | 只有 `owns_tray` 的窗口挂图标；该窗口在 redirect 模式下隐藏而不关闭，新窗口正常关闭 |
| 认领归属 | 每个窗口自己扫，先到先得 | 只有 `LAST_ACTIVE`（最后激活）的窗口认领；托盘隐藏且无其它可见窗口时才由它兜底 |
| 预留标签 | —— | 有 view-less 标签（自己 spawn 的文件夹）的窗口有无条件优先权 |
| 内存 | 每个窗口的 `Box<App>` 永不释放 | `WM_NCDESTROY` 里释放 App + 销毁 HACCEL |

已知未做（留给 M3.2b/c）：BHO 的 `FindWindowW("RevolcMain")` 仍只命中“某一个”窗口，托盘菜单还没有窗口列表，
`WM_ACTIVATE` 的输入队列挂载已按「谁是最后激活」判定，但还没做多窗口下的顺序压力测试。

### 二阶段的参照系（REA 取证，2026-11-18）

详见 `clover/analysis/Clover_MultiWindow_And_Tray_Evidence.md`（仓库外，与 `clover/` 同目录）。要点：

- Clover 的多窗口 / 单实例 / 转发 / 任务栏归组**全部是 Chromium 原生**：`BrowserList`、`ProcessSingleton`
  （mutex `Local\ChromeProcessSingletonStartup!` + `WM_COPYDATA` 四段式 payload）、`app_id`。
- **托盘不是**：clover.dll / clover.exe / TabHelper32 / TabHelper64 都没有 `Shell_NotifyIcon` 导入，字节搜索也零命中；
  `Clover_StatusTrayWindow` 只是一个类名字符串。托盘实现不在解包产物里。
- 吸收是 **push**：`FinderExplorerThread` 属于 `WebContentsImpl`（一个 tab 一个），先建 tab 再等窗口；Revolc 是 pull（先有窗口再认领）。
- 外部启动路径读 `--new-window`：为真时**不复用活动窗口**，直接新建。这是「只想打开一个文件夹却多出一个窗口」的来源。
  **Revolc 不要沿用**：新建窗口只能由显式动作触发（托盘菜单 / Ctrl+N / 拖 tab 出窗），任何打开路径的兜底都是
  「最近活动窗口加 tab」。

## 3. 本次踩过的坑（血泪经验，勿重蹈）
1. **COM DLL 的 HRESULT 不能想当然**：`GetSite` 返回 `Error::empty()`（=S_OK）但没写 `ppvsite`，Explorer 拿未初始化指针 → explorerframe.dll+0x4d29a COM 同一性比较崩 79 次。必须返回真失败码（E_FAIL）。
2. **BHO SetSite 里不要 QI site / 读其属性**：窗口创建期对 site 做复杂 COM 调用会破坏 explorerframe 状态（二分法实证）。只发消息，HWND 让 Revolc 自己找。
3. **提权窗口收不到低完整性进程的 PostMessage**（UIPI 静默丢，err=5）：管理员终端启动的 Revolc 收不到 Explorer 通知。修复：`ChangeWindowMessageFilterEx(MSGFLT_ALLOW)`。
4. **单实例必须强制**：双实例时 BHO 的 FindWindowW 把 HWND 送错实例 → 同窗口被吸收两次 → 僵尸。互斥锁 `Local\RevolcSingleInstance`。
5. **吸收要 SetParent 先行**：先阻塞解析路径（20×50ms）再吸收曾造成 1.7s 可见延迟。元数据后补，标签用窗口标题兜底。
6. **杀 Revolc 进程 = 杀掉被吸收的 Explorer 窗口**（子窗口随宿主销毁）。安全网已加：控制台 Ctrl handler→WM_CLOSE、WM_ENDSESSION→release_all；但任务管理器强杀仍无法拦截。关闭请走 UI/托盘。
7. **注册/注销必须显式验证**：regsvr32 /s 静默吞错；PowerShell 位数导致注册表视图重定向（HKLM Classes → WOW6432Node）。用 `reg.exe /reg:64` + query 验证。
8. **Release 构建的 BHO 才能进 Explorer**；`DllCanUnloadNow` 恒 S_FALSE。
9. 排错工具链：事件日志 Id=1000 聚类（模块+offset）；WER 报告批量解析脚本 `D:\Projects\file-explorer\log\261117\analyze_wer.py`；`%APPDATA%\revolc\bho.log`（BHO 侧）、`%APPDATA%\revolc\logs\`（主程序侧）。

## 7. 排错速查（新增）

| 现象 | 先看 |
|---|---|
| 文件夹留在系统 FE | `revolc.log` 有没有 `sweep adopting stray folder windows`；没有则是扫描被挡（Revolc 提权而 Explorer 中完整性 → SetParent 失败，日志有 `absorb failed, parking window`） |
| 开 tab 卡住/白屏 | `SWP_ASYNCWINDOWPOS` 被去掉过？跨进程同步 SetWindowPos 会阻塞在 Explorer 输入队列 |
| BHO 是否被加载 | 建 `%APPDATA%\revolc\bho.debug` 后再开窗口，看 `bho.log` 有没有 `SetSite (notify only)` |
| 窗口存在与否 | `cargo run --release --example list_windows`（列出所有 CabinetWClass + PID + 可见性 + 父窗口） |
| 优雅退出 | `revolc.exe --shutdown`（**别 taskkill**，子窗口跟着死） |

注意：沙箱/隔离桌面里跑的进程看不到真实桌面的窗口，`list_windows` 与 `--shutdown` 必须在用户正常终端里跑。
